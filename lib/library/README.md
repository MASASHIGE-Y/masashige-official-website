# Knowledge Library のコンテンツ管理

DB・APIキー・外部CMSは使いません。更新はリポジトリの変更と通常のデプロイで反映されます。

## ファイル

- `types.ts`: 分野、カテゴリー、テーマ、発信元、動画・記事の型。
- `catalog.ts`: 分類とテーマの導入文・比較の問い、参考チャンネル。
- `resources.ts`: 個別の動画・記事。
- `queries.ts`: 公開データの取得、内部リンク、YouTube時刻付きリンク。
- `metadata.ts`: Libraryのページ別metadata。
- `presentation.ts`: 分野別の写真、見出し、写真の出典。

## 動画を追加する

1. `catalog.ts` の `sources` に発信元があるか確認します。なければ公式URLと一意のIDを追加します。
2. `resources.ts` に `VideoResource` を追加します。タイトルと発信元を公式情報で確認し、YouTubeの動画IDを `videoId` に指定します。
3. `topicIds` に既存のテーマIDを指定します。新しいテーマの場合は `catalog.ts` に追加します。
4. 視聴前は `review: { status: "unwatched" }` にします。タイトル確認日と視聴確認日は別の情報です。
5. 公開するものだけ `published: true` にします。非公開資料や個人メモは、この公開リポジトリに保存しないでください。`published: false` は機密保護ではありません。

## メモ・タイムスタンプ

`timestamps` に秒数、見出し、作成元を入れると、YouTubeの該当時刻へのリンクになります。
投稿者が公開したチャプターは `origin: "publisher"`、自分の視聴メモは `origin: "editor"` とします。
確認していない時刻は登録しません。

視聴後は `review.status` を `reviewed` にし、次を記録します。

- `reviewedAt` / `reviewer`: 視聴日と記録者。
- `sourceNotes`: 発信者の説明を自分の言葉で短くまとめ、動画内の秒数を添える。
- `interpretation`: 自分の解釈や考察。発信者の主張と分ける。
- `evidence`: 論文・公的資料等のURLと、その資料が何を支えるのか。

字幕や文字起こしの大量転載、動画ファイルの保存は行いません。

## 記事と関連付け

記事は `ArticleResource` として、著者・更新日・段落・関連テーマを登録できます。
`relatedResourceIds` に資料IDを入れると関連動画・記事へのリンクが表示されます。
テーマ間の関連は `relatedTopicIds` で指定します。
本文が長くなった段階でMarkdown等の導入を検討します。

## 公開ページ

- `/library` → 分野 → カテゴリー → テーマの順に進めます。
- 動画の分類は編集上の目安です。内容を確認するまでは、理論の要約や評価として扱いません。
- 公開資料があるテーマだけ詳細ページを生成します。資料がない分類は分野ページで準備状況を表示します。
- URLのslugは公開後に変更しないことを基本とします。
- 英語分野は発音・リスニング・学習方法を公開しています。資料がない分類は準備中の表示です。
- Library本文は日本語です。公式HPの日英切り替えとは独立しており、英語UIからの入口ではその旨を示します。
