# WAGAYA. の編集室

## 現在の範囲

- `/studio` にSanity Studioを組み込む。
- 日英の文言をセクション別に編集する。リンク先や配列構造は文言編集から変更できない。
- ShigeのYouTubeチャンネルURL、家の紹介動画URLを編集する。
- Libraryの動画タイトル・YouTube URL・発信元・既存テーマを編集する。
- 写真アップロード、ブログ、読者会員、一般向け新規登録は含めない。
- サイトのmetadata、カテゴリー・テーマの追加、記事本文、レイアウトは引き続きコード管理。

## Freeプランの前提

2026-11-14時点の公式料金表: https://www.sanity.io/pricing

月額$0、公開データセット2個、文書10,000件、月250,000 APIリクエスト・1,000,000 CDNリクエスト。
Freeの権限はAdministratorとViewer。ShigeだけをAdministratorにする。
非公開データセットやEditorロールはFreeには含まれない。利用量はSanityの管理画面で確認する。
Vercel側の利用量・料金は別。課金プランの変更は自動では行わない。

公開文書はサイト画面で使わないフィールドも公開APIから読める。秘密情報・個人情報・非公開メモを保存しない。
Sanity標準の下書きは未認証の読み取りから除外される。任意の `published: false` フィールドで秘密情報を保護しない。

## 接続手順

1. Shige本人がSanityに登録し、Freeプランのプロジェクトを作成する。契約への同意は本人が行う。
2. `production` という公開データセットを用意する。メンバー一覧で編集権限を持つ人がShigeだけであることを確認する。
3. `.env.example` に示した公開識別子を、ローカルとVercelの環境設定へ登録する。Project IDは秘密値ではない。書き込みトークンは不要で、チャットへ貼らない。
4. SanityのAPI/CORS設定へ実際に使う編集室のoriginを登録する。ローカルは `http://localhost:3003`、本番は `https://masashige-official-website.vercel.app`。Studioの認証に必要なcredentialsを許可する。ワイルドカードでは登録しない。
5. 開発サーバーを再起動し、`/studio` へアクセスしてShigeのSanityアカウントでログインする。
6. 「初期データ」で現在公開中の文言と動画を取り込む。この操作はSanityへ公開文書を書き込み、CMSの動画表示へ切り替える。既存の同一IDの文書は上書きしない。
7. 文章と動画を1件ずつ変更し、下書き中は公開側に出ないこと、Publish後に反映されること、ログアウト状態では書き込めないことを実機確認する。
8. 接続確認後、別途承認を得てPR・本番反映を行う。

Sanityの未接続時は既存ファイルの掲載内容を表示し、編集室には未接続と表示する。
接続後にAPIが失敗した場合は成功扱いの空データへ置き換えず、再生成を失敗させる。ISRに以前の正常なページがある場合はNext.jsがそのページを維持する。

## 日常の更新

編集室で変更するとSanity標準の下書きになる。Publishするまでは公開サイトに出ない。
公開後の内容取得・ページ再生成は60秒間隔のISR。60秒経過後のアクセスが再生成を始めるため、反映が必ず60秒以内になるという保証ではない。
ブラウザ内の既存ページは自動では書き換わらない。公開後、時間を置いて再読み込みして確認する。

CMS動画の切り替え後は、動画の追加・変更・非公開化をSanityで行う。最後の動画を非公開にしたテーマは一覧とsitemapから外れる。
既存動画の出演者・関連資料・視聴記録は現在のコードのデータを維持する。これらのCMS編集は今回の対象外。
文言の項目を削除すると、その項目はコード内の初期値に戻る。

## 安全境界と検証

- 編集の認証・認可はSanity APIのプロジェクトメンバー権限で強制する。編集画面を隠すだけの方式ではない。
- 公開側は匿名・`published` perspectiveで読む。秘密の読み取り・書き込みトークンをブラウザへ渡さない。
- 公開する文言のIDは `siteText-<section>` を使用する。Sanityではドットを含むIDが匿名取得できないため、`siteText.<section>` に戻さない（https://www.sanity.io/docs/content-lake/ids）。
- YouTube URL・テーマID・日英文言を実行時にも検証し、任意HTMLや任意の設定キーは受け付けない。
- Sanity向けのCSP接続許可は `/studio` だけに追加する。一般ページとGoogleフォームの既存制限は維持する。
- `npm run test:security` はURL・型・参照先・公開取得・失敗経路・CSP・既存lintルールを検証する。
- `npx sanity schema extract --path /tmp/wagaya-sanity-schema.json` はログインなしでスキーマを検証する。
- `@vercel/frameworks` 配下の `js-yaml` と `smol-toml` は脆弱性修正済みバージョンへ限定override。CLIのYAML/TOML解析テストも実施する。上流で修正されたらoverrideを再検討する。
- パッケージはES module形式を明示し、NodeのテストからTypeScriptの検証関数を実行する。依存パッケージのmodule形式は変更しない。
